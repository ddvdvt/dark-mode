# Тёмный режим

**Статус: 1.1.0, готово к отправке в Chrome Web Store.** Что изменилось с 1.0.0 — в разделе [«Проверка на типах сайтов»](#проверка-на-типах-сайтов-110). Тексты карточки, ответы для проверки, скриншоты и промо-картинки лежат в [`store/`](store/). Перед отправкой нужно заменить адрес сайта `BASE` в [`extension/lib/brand.js`](extension/lib/brand.js) и `homepage_url` в манифесте (см. ниже).

Расширение для Chrome/Edge, которое включает тёмную тему на любом сайте — быстро, без белой вспышки при загрузке и бесплатно навсегда. Без аккаунта, рекламы и аналитики.

## Возможности

- **Без белой вспышки.** Тема включается до первой отрисовки страницы: в манифесте есть крошечный CSS на `document_start` (тёмный холст), а скрипт успевает прочитать настройки и применить тему за единицы миллисекунд. Время применения видно в окне расширения.
- **Два режима:**
  - **Умный** (по умолчанию). Читает таблицы стилей самой страницы и создаёт рядом с каждой «перекрашенную» копию, где остались только цветовые свойства: фон, текст, рамки, градиенты, тени, `fill`/`stroke`, CSS-переменные (роль переменной — фон, текст или рамка — определяется по тому, где она используется, в том числе в других файлах стилей). Копия вставляется сразу за оригиналом, поэтому селекторы, специфичность, `!important`, `@media`, `@supports`, `@layer`, `@container`, вложенные правила и `@keyframes` работают как раньше. Картинки и видео не трогаются, вёрстка не меняется. То, что нельзя переписать (CSS с другого домена, `style="..."`, старые атрибуты `bgcolor`/`color`/`link`, `fill`/`stroke` у SVG, `::before`/`::after` из чужого CSS), обрабатывается запасным путём по вычисленным стилям — порциями в `requestIdleCallback`, с кэшем цветов и учётом наследования (одно правило на каждую пару цветов, а не на элемент).
    - Понимает приёмы популярных фреймворков: Tailwind 3 (`rgb(255 255 255 / var(--tw-bg-opacity))`), Tailwind 4 (`oklch`, `color-mix()`), Bootstrap 5 и shadcn/ui (переменные с каналами: `rgba(var(--bs-x-rgb), .5)`, `hsl(var(--background))`), все синтаксисы цветов CSS (`lab`, `lch`, `hwb`, `color()`, `light-dark()`, `color-mix()`, системные цвета). Переменная, которая служит и цветом текста, и фоном (`--color-white` в Tailwind 4), получает отдельное значение для каждой роли — белый текст на кнопке не становится тёмным.
    - Светлота переносится по воспринимаемой яркости, а не по HSL: жёлтые, красные и синие кнопки и ссылки сохраняют оттенок и читаемость.
    - Shadow DOM: открытые и закрытые теневые деревья, `<style>` внутри них, `adoptedStyleSheets` (и у `document`); стили CSS-in-JS (`insertRule`) перекрашиваются до того, как компонент нарисуется.
    - Значки на CSS-масках (`mask-image`) и фоны диаграмм в SVG перекрашиваются как знаки, а не как фон.
  - **Быстрый.** Один CSS-фильтр на `<html>` (`invert` + `hue-rotate`, оттенки сохраняются), фото, видео, `canvas`, встроенные плееры и большие фоновые картинки (в том числе подгружаемые позже) возвращаются в исходные цвета; повторяющиеся текстуры и обёртки размером со страницу — нет. Крупные тёмные блоки светлой страницы (шапка, подвал, тёмная полоса) остаются в своих цветах, а не становятся светлыми. Работу делает компоновщик браузера, JavaScript почти не нужен. Хорош для очень тяжёлых страниц. Если страница слишком велика для умного режима (больше 60 000 CSS-правил или элементов при полном сканировании), расширение само переключается на быстрый и пишет об этом в окне.
- **Уже тёмные сайты не трогаются.** После загрузки (и ещё раз через 1,5 с — для одностраничных приложений) расширение на мгновение отключает свои стили и смотрит фон холста (с учётом `<meta name="color-scheme">`) и фон в 9 точках экрана; точки на фото, видео и `canvas` не считаются (светлый сайт с чёрным плеером посередине не принимается за тёмный). На светлом холсте тёмными должны быть все точки, на тёмном — большинство. Если сайт уже тёмный — расширение оставляет его как есть. Кнопка «Всё равно затемнить» в окне меняет решение для сайта.
- **Без мерцания.** Когда тема включается, выключается или страница проверяется, переходы CSS (`transition`), которые это вызвало, сразу завершаются: элементы с `transition: all` не «переливаются» из светлого в тёмное.
- **Печать — в цветах сайта.** Все стили расширения действуют только на экране (`@media screen`).
- **Не ломает страницы.** Меняются только цвета; e2e-тест сравнивает размеры и положение элементов с темой и без — они совпадают. Поля ввода остаются читаемыми (`color-scheme: dark` для встроенных элементов управления). Фреймы на странице тоже затемняются (в быстром режиме их уже инвертирует фильтр родителя, повторно не применяется). Полноэкранное видео не инвертируется. Весь код обёрнут в `try/catch`, повторный запуск скрипта ничего не делает.
- **Окно расширения:** общий выключатель, состояние текущего сайта, «Выключить/Включить на этом сайте», режим для сайта, яркость, контраст и сепия.
- **Расписание:** всегда, как в системе (`prefers-color-scheme`) или по времени (например, с 20:00 до 07:00, переключается само в нужную минуту).
- **Горячие клавиши:** `Alt+Shift+L` — включить/выключить на текущем сайте; «везде» — назначается вручную. Сочетание не занято самим Chrome (у Chrome с `Alt+Shift` заняты I, T, A и N) и не совпадает с сочетаниями популярного аналога (`Alt+Shift+D`/`Alt+Shift+A`), чтобы оба расширения можно было держать при переходе. Изменить: `chrome://extensions/shortcuts` (кнопка есть в настройках).
- **Список сайтов** на странице настроек: «не затемнять», «затемнять всегда», режим для сайта. Правило для `example.com` действует на поддомены. Экспорт и импорт в JSON.
- Интерфейс на русском, английском и казахском.

## Установка (распакованное расширение)

1. Скачайте или клонируйте репозиторий.
2. Откройте `chrome://extensions` (в Edge — `edge://extensions`) и включите «Режим разработчика».
3. Нажмите «Загрузить распакованное» и выберите папку `extension/`.
4. Вкладки, открытые до установки, перезагрузите.

## Разрешения и зачем они нужны

| Разрешение | Зачем |
|---|---|
| Скрипт на всех сайтах (`content_scripts`, `<all_urls>`, `document_start`) | Тёмная тема нужна на каждой открытой странице, и её надо применить **до первой отрисовки**, иначе будет белая вспышка. С `activeTab` так нельзя: он требует клика на каждой странице и срабатывает, когда страница уже показана. Скрипт работает только локально: читает стили страницы и добавляет свои. Содержимое страниц, формы и адреса никуда не отправляются и не сохраняются. |
| `storage` | Хранить настройки и список сайтов локально в браузере. |

Больше ничего: нет `host_permissions`, `tabs`, `scripting`, `webRequest`, `web_accessible_resources`. Сетевых запросов расширение не делает (это проверяет `npm test`).

## Конфиденциальность

Всё хранится только в вашем браузере, на сервер ничего не отправляется. В расширении нет аналитики, рекламы и аккаунтов. Подробнее — в [PRIVACY.md](PRIVACY.md).

## Страницы на сайте автора

После установки открывается вкладка `BASE/welcome/dark-mode.html`, после удаления — `BASE/bye/dark-mode.html`, ссылка «Другие расширения автора» ведёт на `BASE/#dark-mode`, а `homepage_url` — на `BASE`. Адрес `BASE` задан в одном месте: [`extension/lib/brand.js`](extension/lib/brand.js) (сейчас там заглушка `https://USER.github.io/REPO/`). После замены поменяйте и `homepage_url` в `extension/manifest.json` — `npm test` проверяет, что они совпадают.

## Производительность

`npm run perf` загружает сгенерированную тяжёлую локальную страницу ([`e2e/heavy.mjs`](e2e/heavy.mjs)): 6 000 элементов, 3 000 CSS-правил (цвета, градиенты, переменные, `@media`, `:hover`), встроенные стили; после загрузки страница ещё 10 раз подряд добавляет по 20 карточек (≈1 000 элементов, как бесконечная лента). Каждый режим — 5 загрузок, в таблице медианы. Долгие задачи (long tasks > 50 мс) собирает `PerformanceObserver` на странице — в них попадает и работа скрипта расширения, он выполняется в том же потоке. TBT — сумма превышений 50 мс.

Chromium 149 (headless, `--disable-gpu`), Windows 11, общий компьютер (параллельно работали другие программы, разброс между прогонами — до 10–15 %); результаты в [`e2e/perf-results.json`](e2e/perf-results.json). Столбец «1.0.0» — та же версия 1.0.0, замеренная заново на этом же компьютере в тот же день, чтобы сравнение было честным.

Как читать:

- «Тема применена» — от старта скрипта до включённой темы, включая чтение настроек. В умном режиме сюда входит перекраска уже загруженных стилей: ~35 мс на 3 000 правил (один проход по CSSOM, кэш разобранных цветов).
- «Выключено» — расширение установлено, но выключено: скрипт только читает настройки и выходит. Нагрузки он не добавляет.
- **Быстрый режим** не создаёт долгих задач вообще. `load` у него позже базы на ~45 мс — это отрисовка полноэкранного фильтра в программном рендеринге (`--disable-gpu` в безголовом режиме); на обычном компьютере с GPU фильтр дешевле, но это не измерялось.
- **Умный режим** на этой нарочно тяжёлой странице добавляет одну долгую задачу при загрузке (самая долгая задача ~70 мс включает и разбор HTML самой страницей) и сдвигает FCP на ~50 мс: браузер разбирает перекрашенные стили и пересчитывает стили 6 000 элементов. Пока лента растёт, долгих задач нет ни в одном режиме: новые стили перекрашиваются сразу (до следующего кадра), новые элементы — в простое.
- **По сравнению с 1.0.0** перекраска стилей стала дороже на ~4 мс на 3 000 правил (+13 %): это цена перевода светлоты по воспринимаемой яркости и отдельных значений переменных для текста и фона. Зато запасной путь и обработка изменений DOM дешевле (элемент, добавленный вместе с потомками, больше не обходится заново для каждого предка), так что общее время работы скрипта на главном потоке осталось прежним. Проверка всех элементов при CSS с другого домена теперь ещё и перекрашивает `::before`/`::after` — при этом стоит столько же, сколько в 1.0.0 (всё в простое, ни одной долгой задачи). На страницах без `transition` в CSS защита от «переливания» цветов не включается и ничего не стоит.

## Проверка на типах сайтов (1.1.0)

Кроме смоук-теста, `npm run test:e2e` прогоняет корпус из 27 синтетических страниц в [`e2e/sites/`](e2e/sites/) — они воспроизводят устройство DOM и CSS реальных типов сайтов (своя разметка, без копий чужого кода): «Википедия» (картинка-логотип, значки на масках, инфобокс, таблицы, формулы и схема в SVG), GitHub (токены в отдельном файле, `prefers-color-scheme`, подсветка кода, octicons), Tailwind 3 и 4, Bootstrap 5, SPA на CSS-in-JS (shadcn-переменные, `insertRule`, перерисовки), веб-компоненты (Shadow DOM, `adoptedStyleSheets`, закрытый корень, декларативный Shadow DOM), документ и карта на `canvas`, видеохостинг, лента фото, новостной сайт (CSS с CDN, асинхронный CSS, ленивые картинки, `<picture>`, рекламный фрейм), старый форум и дерево комментариев, письмо в веб-почте, просмотрщик PDF, блог с кодом, «`!important` везде», формы, уже тёмный / наполовину тёмный сайт, `<meta name="color-scheme">`, фреймы (в том числе `about:blank`, записанный скриптом, и `srcdoc`), огромная и постоянно меняющаяся страница, текст на фото и графики, переходы, «менеджер `<head>`», который удаляет чужие стили.

Каждая страница открывается без темы и с темой в обоих режимах, проверяются измеримые свойства ([`e2e/sites.mjs`](e2e/sites.mjs), измерения — [`e2e/analyze.mjs`](e2e/analyze.mjs)): тёмный фон по пикселям снимка, контраст видимого текста по WCAG (4,5, для крупного — 3; не хуже, чем у самой страницы), значков (≥ 3), сохранение оттенка фирменных цветов, светлые `::before`/`::after`, пиксели картинок/видео/`canvas` (в умном режиме не меняются, в быстром — возвращены в исходные цвета), одинаковые размеры и положение элементов, ошибки в консоли, долгие задачи на меняющихся страницах, печать, фреймы, полное восстановление вычисленных цветов после выключения, «уже тёмные» сайты не тронуты. В 1.0.0 из 54 прогонов проходили 30.

Найдено и исправлено (по шаблонам сайтов): Tailwind 3 с прозрачностью через переменную оставался белым; переменные-каналы Bootstrap и shadcn не перекрашивались; общие для текста и фона переменные (Tailwind 4) давали тёмный текст на тёмной кнопке; токены в отдельном файле (GitHub) получали неверную роль; жёлтые и красные кнопки и синие ссылки теряли контраст; не разбирались `color-mix()`, `light-dark()`, `lab()`, `lch()`, `hwb()`, `color()`; значки на CSS-масках и фон схем в SVG оставались тёмными/белыми; Shadow DOM и `adoptedStyleSheets` не перекрашивались; стили CSS-in-JS отставали до 1 с; светлый сайт с чёрным плеером посередине и сайт с `transition` на фоне (нашлось на habr.com) принимались за тёмные, а сайт с `<meta name="color-scheme" content="dark">` — нет; при включении и проверках элементы с `transition` «переливались»; печать была тёмной; фрейм `about:blank`, записанный через `document.write`, оставался без темы; ссылки `<body link>` на старых форумах были тёмными на тёмном; `style="…!important"` не перекрашивался; после изменения встроенного стиля оставался старый цвет; стили, удалённые «менеджером `<head>`», не возвращались; `rel=preload → stylesheet` отставал до 1 с; `::before`/`::after` из CSS с другого домена (затухание у вкладок на habr.com) оставались белыми. В быстром режиме: картинки внутри возвращённых в цвет блоков инвертировались дважды; обёртка с текстурой во всю страницу делала её снова светлой; тёмные шапка и подвал становились светлыми; ленивые фоновые превью оставались негативом.

Честно об ограничениях:

- Сравнение с другими расширениями не проводилось — только с самой страницей без темы.
- Картинки в умном режиме не меняются: тёмные логотипы-надписи и формулы, вставленные как `<img>` (например, на «Википедии»), остаются тёмными; светлые фоновые картинки-текстуры остаются светлыми. Содержимое, нарисованное на `canvas` (страницы в редакторах документов и просмотрщиках PDF, графики), остаётся как есть — белые страницы остаются белыми в обоих режимах (в быстром режиме `canvas` возвращается в исходные цвета).
- В быстром режиме цветные эмодзи, иконки-SVG в `<img>` и мелкие иконки-спрайты инвертируются (крупные фото и видео — нет); фото в рекламных фреймах с другого домена инвертируются вместе со страницей; цвета повторно инвертированных фото слегка отличаются из-за ограничений CSS-фильтров. Светлый блок внутри тёмной шапки, оставленной в своих цветах, тоже остаётся светлым.
- Переменные CSS, заданные только во встроенном стиле или скриптом (`style="--accent: …"`), не перекрашиваются (их значение неизвестно заранее); если такая переменная одновременно задана и в CSS, для её частей страницы действует значение из CSS.
- Переход (`transition`), заданный только во встроенном стиле элемента, может один раз проиграться при включении темы (защита включается, когда переходы есть в CSS страницы или CSS недоступен).
- Правила CSS-in-JS, добавленные без единого изменения DOM в той же задаче, подхватываются опросом раз в секунду; `adoptedStyleSheets`, назначенные компоненту позже, — тоже.
- Настройки читаются асинхронно (синхронного хранилища у content-скриптов нет): содержимое, которое скрипты страницы рисуют, пока она ещё разбирается, может один кадр показаться в исходных цветах на уже тёмном холсте. Если страница грузится очень медленно, а сайт выключен в списке, до решения скрипта на долю секунды может мелькнуть тёмный холст (обратная белая вспышка невозможна).
- `::selection`, `::placeholder`, `::marker` и полосы прокрутки из CSS с другого домена не перекрашиваются (запасной путь видит только `::before`/`::after`).
- Служебные страницы браузера и магазин расширений изменить нельзя.

```
npm test              # модульные тесты (node:test): цвета, перекраска CSS, настройки, анализ страницы, проверки релиза
npm run test:e2e      # смоук-тест + корпус типов сайтов в установленном Chromium (playwright-core), ~4 мин
npm run test:sites    # только корпус: SITES=wiki,github MODES=dynamic npm run test:sites — выборочно
npm run perf          # замер производительности (см. выше), пишет e2e/perf-results.json
npm run zip           # архив dist/dark-mode-<версия>.zip для Chrome Web Store (с проверкой содержимого)
npm run store:images  # скриншоты 1280×800 и промо-картинки в store/ (настоящий интерфейс, локальная страница из store/fixtures/)
npm run icons         # перегенерировать иконки
node scripts/locales.src.mjs   # пересобрать _locales из единого источника
```

Устройство кода:

- `extension/lib/` — чистая логика без `chrome.*` и DOM. Файлы — обычные скрипты (без `import`/`export`), потому что content-скрипты в MV3 не могут быть модулями; они публикуют функции в `globalThis.DarkModeLib`, а страницы и тесты подключают их как модули ради побочного эффекта:
  - `color.js` — разбор цветов (все синтаксисы CSS Color 4/5: hex, rgb, hsl, hwb, lab, lch, oklab, oklch, color(), color-mix(), light-dark(), именованные; системные цвета распознаются), перекраска по роли (фон, текст, рамка, тень) с сохранением воспринимаемой яркости, цепочка CSS-фильтров;
  - `css-transform.js` — перекраска таблицы стилей (CSSOM → план → CSS-текст): роли переменных по всем таблицам, переменные-каналы, отдельные значения переменной для каждой роли, маски;
  - `settings.js` — настройки, правила сайтов, расписание, решение «затемнять ли», экспорт/импорт;
  - `page-analysis.js` — «уже тёмный ли сайт» (сетка 3×3, схема цветов), запасной путь для элементов, `::before`/`::after` и SVG, эвристики быстрого режима (фото, текстуры, тёмные блоки);
  - `brand.js` — адреса сайта автора (ES-модуль, используется только страницами и service worker).
- `extension/src/content/` — content-скрипты: `preload.css`, `dom-util.js` (общие помощники, гашение переходов), `filter-engine.js`, `dynamic-engine.js`, `content.js` (точка входа).
- `extension/src/` — окно расширения, страница настроек, service worker.
- Внешних зависимостей во время работы нет. Для разработки нужен только `playwright-core`, он запускает уже установленный Chromium. Тесты ходят только на локальные страницы (`e2e/fixtures`, `e2e/sites`, `127.0.0.1`/`localhost`; второй адрес — для «чужого» домена). Ручная проверка на настоящих сайтах делалась вне тестов; её снимки, если есть, лежат в `e2e/.live/` и в репозиторий не попадают.
